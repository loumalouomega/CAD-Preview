# CLAUDE.md

Project memory for CAD-Preview — a VS Code extension that previews and edits 3D CAD/mesh files in a custom editor. Edits persist to sidecar files beside the source; the source itself is written only by an explicit, confirmed save.

**This file holds invariants, traps and conventions — not history.** It was trimmed from 1.2 MB to the essentials. Per-feature design write-ups, probe trails and verification logs live in git: `git show eb454bc:CLAUDE.md` is the last full version (source comments and `doc/` still cite its old section titles — look them up there). Release history is `CHANGELOG.md`; user-facing behaviour is `doc/`; open work is `doc/roadmap.md`.

## Working rules

- **Keep docs in sync, as part of the change.** New/changed protocol message → `doc/protocol.md`. File-format behaviour → `doc/file-formats.md` + the format tables in `README.md` / `doc/index.md` / `doc/getting-started.md`. Module/exported function/architecture → `doc/extension-host-api.md` or `doc/webview-api.md`. Toolbar/UI → `doc/getting-started.md` tables. Pure internal refactors need nothing.
- **Keep the MCP server in sync** (`src/mcpServer.ts`, `src/mcpTools.ts`, `doc/mcp-server.md`):
  - New `EditOp` kind → add its `OP_PARAM_DOCS` entry in `src/opCommands.ts` (`opCommands.test.ts` fails until you do). Tool schemas need no edit (raw ops pass `validateEditOp`).
  - New `MeshOptions` field / mesh export format → inherited from the shared registries; check `describe_capabilities` and the doc still match.
  - Sidecar schema/filename change → update `src/mcpSidecars.ts` in the same commit (must stay byte-compatible with what `provider.ts` reads).
  - New `provider.ts` export/meshing flow (e.g. a companion-file rule) → mirror it in `mcpTools.ts` and extend `scripts/mcp-smoke/run.mjs`.
  - A feature moving between headless-capable and webview-only → update the capability matrix in `doc/mcp-server.md` and the limitation messages.
- **Screenshots are generated, never hand-captured** (`npm run docs:screenshots` → `doc/public/screenshots/` + two `images/` README heroes). Any change to viewer markup/toolbar/a panel means re-running it. Rules:
  - The harness renders the exact shipped DOM from `src/viewerDom.ts`'s `viewerBodyHtml()`; `capture.mjs`'s `populate()` must post `"viewState"` (even `{view: null}`) after `"geometry"` or every 3D shot is silently misframed.
  - Several shots use a fixed `clip`; a menu that grows a row gets its last entry cut off while the run still exits 0. Check the clip when adding a menu item.
  - **Inspect the images (at least `viewer-main.png`/`mesh-overlay.png`), not the exit code.** Chromium rasterization isn't bit-reproducible (~0.01% AA churn on unmodified code) — revert PNGs you have no reason to expect changed.
- **Releases:** bump with `npm version <x.y.z> --no-git-tag-version`, **never sed** (a blanket sed once rewrote `ipaddr.js` in the lockfile to an unpublished version and broke `npm ci`). Add a new `## [X.Y.Z] - date` section at the top of `CHANGELOG.md` (never rename the previous one) from the actual commits since the last tag, plus its compare link at the bottom. Run `npm ci` and `npm outdated` for the kernel packages first. **Never move a pushed tag** — a tag push is the release trigger (CI builds it, publishes it to the Marketplace, creates the release); amend before tagging or cut a new version after tagging.
- **`vitest` / `mcp:smoke` only mean something against the lockfile.** A drifted `node_modules` manufactures convincing fake reds (an old `@meshioplusplus/wasm` once failed BigInt tests and XDMF imports). "Reproduces without my change" rules out your change, not the tree. CI runs `npm ci` and is the arbiter.
- **Closing a roadmap item:** remove it from `doc/roadmap.md` entirely (not struck through). Add to `CLAUDE.md` **only** what a future change could break: invariants, non-obvious traps, dead APIs, verified call shapes. Probe trails, measurements and "verified by…" narratives belong in the commit message / `CHANGELOG.md`, not here.
- **Unverified claims go in `scripts/verification-gaps/registry.json`**, not in this file (see Testing). Never write a prose "verification gap" paragraph here.
- **License is GPL-3.0-or-later** (forced by statically linked Gmsh/OCCT WASM and the OpenSCAD-WASM roadmap item). **Before adding any dependency that gets bundled into the `.vsix`, check its license is GPL-compatible.** Accepted: MMG (LGPL-3.0-or-later), fTetWild (MPL-2.0, "Incompatible With Secondary Licenses" not invoked), draco3d (Apache-2.0), meshoptimizer/MCP SDK/zod (MIT), node-hid (MIT OR X11). See README "Licensing".
- **Verify probe-first.** For any OCCT/Gmsh/meshio++ call you haven't used before, probe the live WASM (`npm run probe`) before writing code. "Green in the API manifest" has repeatedly been necessary but not sufficient (see Kernel facts).

## Architecture invariants

- **OCCT runs host-side, never in the webview.** The host parses/tessellates and posts plain typed-array buffers (base64); the webview runs only Three.js. Opening a pure-mesh file must never load a WASM (lazy init, memoized singletons, never in `activate()`).
- **Routing** (`src/fileRouter.ts`): B-rep (`.step/.stp/.iges/.igs/.brep`) → OCCT; mesh (`.stl/.obj/.ply/.gltf/.glb`) → Three.js loaders; meshio formats → host meshio++ → STL boundary; `.csg` → OCCT via `csgModel.ts`; `.scad` → installed `openscad` → `.csg`. Extension lookup matches the **longest registered suffix** (`.post.msh` ≠ `.msh`). `ROUTED_EXTENSIONS` is the one extension list (Models view etc. must use it).
- **Custom editor** is `CustomEditorProvider<CadDocument>`. **The CAD source is never written silently** — no autosave, no watcher side effect. A document is dirty iff its unbaked op tail (`currentEdits.length > currentBakedThrough`) is non-empty on a savable format (step/iges/brep/stl/obj/ply). Source writes happen only via: Ctrl+S on a dirty tab, an Export pick of the source's own format, headless `save_model`.
- **Models view** (`modelsView.ts`): `viewType` is constructor-injected, never imported from `provider.ts` (would drag gmsh/meshio/playwright into the integration bundle).
- **Kernel runs in a forked child** (`kernelWorker.ts` ⇄ `kernelClient.ts`, wire format `kernelIpc.ts`), shared by the extension host and the MCP server.
  - One in-flight call at a time (serialized queue, a rejected call must not wedge the queue). Lazy spawn. Child stdio `["ignore","ignore","pipe","ipc"]` (stdout discarded; stderr forwarded as `[kernel-worker]`).
  - Calls carry `JobOptions {owner, signal, timeoutMs}` (`withJob`); `cancel({owner|jobId})` removes only that owner's queued work or kills the child only if that owner's job is running. Default watchdog 5 min (`cadPreview.kernelTimeoutMinutes`). A kill loses **every** open document's cache in the child; the next call cold-parses (accepted).
  - The per-document live-handle cache (`loadBRepCachedForDocument`) lives **inside the worker**, keyed by `documentKey`; live OCCT handles never cross IPC. `provider.ts` and `mcpTools.ts` talk only to the `Pipeline` interface.
  - **`kernelIpc.marshal` is generic and tagged**: typed arrays round-trip as their exact type; array-element `undefined` and non-finite numbers are tagged (JSON would make them `null`); an unrecognized `ArrayBufferView` throws. Don't pass `BigInt64Array` — convert first (meshio++ ≥ 11.2 returns integer arrays as `BigInt64Array`; `meshioService.numericArray()`).
  - **New `Pipeline` function = touch all of:** the `Pipeline` interface (`mcpTools.ts`), `kernelWorker.ts`'s typed dispatch table, `kernelActivity.ts`'s `KERNELS_BY_FUNCTION` (a compile error until classified; list only kernels the call *definitely* uses), and the `fakePipeline` in `mcpTools.test.ts`.
  - Node `Buffer`s are pooled: never `buf.buffer` without copying (`bytes.slice().buffer` is a *view* of the pool). Same trap in `gltfParser.ts`.
- **Fault recovery.** Each kernel singleton (`_ocPromise`, `_gmshPromise`, `_meshioPromise`, fTetWild, MMG) un-caches on a **rejected init**. A WASM abort **mid-operation** corrupts the instance permanently, so every entry point wraps errors (`wrapOcctFault`/`wrapMeshioFault`/`resetGmsh`/`wrapFtetwildFault`) — each kernel keeps its **own local copy** of the abort vocabulary and they must be updated **together**: `out of bounds|abort|RuntimeError|unreachable|null function|table index|function table|funcref table|wasmtable|signature mismatch` (case-insensitive) **or a message that is bare digits** (a raw OCCT exception pointer). A non-abort error passes through as the *same* instance. "Graceful-degrade" meshio entry points call `resetMeshioIfAbort` instead of throwing. The worker retries a handler once after a kernel-reset error.
- **stdout is the MCP JSON-RPC channel.** `mcpServer.ts`'s first statements rebind `console.log/info/warn/debug` to stderr. Never add `console.log`/`process.stdout.write` anywhere the MCP bundle reaches. gmsh-wasm needs explicit `print`/`printErr` → `console.error` (its default writes straight to fd 1).
- **Webview constraints:** no `eval` (CSP; `paramExpr.ts` is a hand-written interpreter); `prompt()`/`alert()` are blocked (use inline `<input>`); one WebGL context only (cube/gizmo/panes draw into the single renderer via scissor); **no DOM/canvas access at module scope** (vitest has no jsdom — build textures/canvases lazily, as `dotTexture()` and `labelOverlay.ts` do); render **on demand** — any new continuous visual update must call `viewer.requestRender()` or it freezes mid-drag.

## WASM loading and bundling

- **OCCT:** never use `initOpenCascade` (ignores `wasmBinary`). Import the raw factory `opencascade.js/dist/opencascade.wasm.js` and pass `wasmBinary` read from `dist/opencascade.wasm.wasm`. `opencascade.js` is **bundled** (not external); `wasmPathPlugin` in `scripts/nodeBundleConfig.mjs` (shared by `esbuild.mjs`, screenshot fixtures and the probe runner) rewrites the `.wasm` import. New WASM package → add to `WASM_EXTERNALS` once.
- **Gmsh** (`@loumalouomega/gmsh-wasm`): load with `createRequire(__filename)(...)` (**not** a static import — its ESM chain has top-level await the CJS bundle can't represent); pass `wasmBinary`; set `General.NumThreads`/`Mesh.MaxNumThreads*` to 1 and read them back (throw if not enforced).
- **meshio++** (`@meshioplusplus/wasm`): ESM-only, no `exports` map → **dynamic `import()`** through `runtimePackage.ts`; always `{variant: "seq"}` (auto picks the threaded build under Node) **and `{full: true}`** — since 17.2.0 the **FULL** artifact is the only one staged (`scripts/runtimeAssets.mjs`; lean and both `_mt` flavours are forbidden in the VSIX), a strict superset of the lean pair: OCCT 7.6.3 (STEP/IGES reading through meshio++ and the `fit_cad` fit), the zstd/lz4 VTK XML codecs, bzip2 libMesh `.bz2` — see README Licensing for the LGPL/OCCT note and the staged `THIRD_PARTY_NOTICES.md`; it self-locates its `.wasm` via `import.meta.url`, so it must stay real files (`dist/meshio/` or `node_modules`), never be inlined or copied elsewhere. Packaging inventory: `scripts/runtimeAssets.mjs` + `.vscodeignore` carve-outs + `compat:vsix`. Since 17.3.0: the adoptable writer set is every format whose writer accepts the bridge's real `generateMesh()` MSH 4.1 (vertex cells included — binary `tecplot`/`.plt` passes; Gmsh's own tecplot writer never did) with a full export→re-open→remesh round trip, and the REJECTED set is upstream-named and pinned in `scripts/gen-1730-fixtures.mjs` (szplt/vtx: build lacks TecIO/ADIOS2; neuroglancer: vertex-only; the pipeline's codec whitelist has **no lzma**, so no meshio++-authored lzma fixture can exist — re-probe before ever claiming it).
- **fTetWild** (`float-tetwild-wasm`): always `{threads: false}` (Node's `threadsSupported()` lies); `Module.wasmBinary` is ignored; `.wasm` located via `import.meta.url`. Use `tetrahedralizeTyped`.
- **MMG** (`@loumalouomega/mmg-wasm`): external CJS, resolved lazily via `createRequire(import.meta.url)` — never import eagerly from `meshioService`. Remesh sets `IPARAM_mem=128` **before** `setMeshSize`; 128 MiB target / 1.5 GiB RSS ceiling.
- **OpenSCAD WASM** (`@loumalouomega/openscad-wasm`): external CJS (`dist/openscad.cjs` via `createRequire` + `resolveRuntimePackage`, like MMG — its lazy `import("./openscad.mjs")` resolves inside the package, so bundling is safe to skip); pass `wasmBinary` read from `dist/openscad-core.wasm` (copied by `esbuild.mjs`, like `gmsh-core.wasm`; the package's own bundled copy is dead weight and is NOT carved back in). Renders fresh per call (`render()` instantiates, ~50-60 ms after the first); no shared instance, so no re-entry hazard. `print`/`printErr` default to stderr-only (MCP-safe); pass `collect` to parse diagnostics.
- **Draco/meshopt** decoders are staged by `esbuild.mjs` `copyDracoDecoders()` (webview + `dist/draco/node/`); the webview build `define`s `import.meta.url` (three's `DRACOLoader` reads it at module scope); CSP needs `'wasm-unsafe-eval'` and `worker-src blob:`.
- **Optional dynamic imports must not be able to `process.exit()`**: `playwright-core` exits the process on Node < 20 at import time, so `renderService.ts` checks the Node major *before* importing (a try/catch can't intercept it). Playwright is a devDependency; `render_snapshot` degrades to `supported:false` without it.
- **OCCT memory discipline (top bug source):** every wrapped OCCT object is a heap handle, not GC'd. Push each into a cleanup list and `.delete()` in reverse in `try/finally` (success and failure). Per-file objects only; the module singleton persists. Cached entries (`BRepCacheEntry`) **alias** reused handles — only ever dispose the latest entry you hold.

## Kernel facts (verified live — don't re-probe)

**Call shapes (use these exact suffixes):**
- Booleans `BRepAlgoAPI_Fuse_3/Cut_3/Common_3(s1, s2)` → `.Shape()`; **`Message_ProgressRange` is not constructible** — pass only the shapes (also why BREP read's 4th arg is `new Handle_Message_ProgressIndicator_1()`).
- Transforms: `gp_Trsf.SetTranslation_1/SetRotation_1(gp_Ax1_2)/SetMirror_3(gp_Ax2_3)/SetScale(gp_Pnt_3,s)`; `gp_GTrsf_1` (suffixed!) + `BRepBuilderAPI_GTransform_2`; rigid via `BRepBuilderAPI_Transform_2(shape,trsf,true)`. `Bnd_Box.Get()` is **unbound** (aborts) — use `CornerMin/CornerMax`. `TopoDS.Orientation` unbound. `TopTools_IndexedMapOfShape` / `IndexedDataMapOfShapeListOfShape` / `MapShapesAndAncestors` unbound → dedup with `HashCode(1<<30)` buckets + `IsSame` (keep deduped handles alive until the end).
- Fillet/chamfer: unsuffixed `BRepFilletAPI_MakeFillet(shape, ChFi3d_Rational)` / `MakeChamfer(shape)`, `.Add_2(amount, TopoDS.Edge_1(e))`, then `.Shape()` + `IsDone()` (not `.Build()`). **Two-radius fillet (probe 2026-10-20, `scripts/probe/examples/occt-var-fillet.ts`):** the prototype carries `Add_1`…`Add_5` and only `Add_3` takes three arguments — `.Add_3(radius1, radius2, edge)` is the two-radius overload, shipped as `FilletOp.radius2` (`variableFilletLaws` in `occtOperations.ts`; constant fillets still take the untouched `Add_2` path). **R1 sits at `BRepAdaptor_Curve_2(edge).Value(FirstParameter())`, NOT at the explorer's first vertex (that is the opposite end)** — verified on all 12 cube edges in both orientations (`occt-var-fillet-orient.ts`). One law per `Add` call, so a chain gets one law per edge: edges are ordered end-to-start by shared endpoints (starting at the end incident to the first listed edge) and the radius is interpolated linearly by cumulative length; anything that is not one open path is skipped with a `fail` diagnostic (`occt-var-fillet-chain.ts`). A radius that does not fit the local geometry (constant 8 on an r = 6 cylinder) **aborts the WASM instance** (`___cxa_is_pointer_type is not defined`) and needs a kernel reset — validate radii before calling (the shipped guard refuses a radius above half the smallest bbox extent of the adjacent faces; OCC bboxes carry ~1e-7 padding, so a planar face's zero extent must be filtered at ≥1e-4 — caught by `mcp:smoke`, which otherwise saw a limit of 1e-7). A closed circular edge has no ends to vary between and degenerates to R1.
- Primitives: `MakeBox_3(pnt,pnt)`, `MakeSphere_5`, `MakeCylinder_3(ax2,r,h)`, `MakeCone_3`, `MakeTorus_5`, `MakeWedge_1/_2`. Wires: `MakeWire_1` + `.Add_1`, `MakeEdge_3(pnt,pnt)`, circle `MakeEdge_8(gp_Circ_2)`, trimmed `MakeEdge_9`, ellipse `_12/_13`, Geom curve via `Handle_Geom_Curve_2` + `MakeEdge_24`, pcurve `MakeEdge_30`; faces `MakeFace_15(wire,true)` (an inner wire becomes a **hole or an island depending on its winding** — decide by 2-D winding sign against the outer wire as `buildSurfaceFromLines` does, then check the area against the shoelace expectation; `.Reversed()` returns a bare `TopoDS_Shape`, cast with `TopoDS.Wire_1`); `BRepBuilderAPI_MakeVertex` and `BRepBuilderAPI_Sewing(tol,true,true,true,false)` have no `_N` ctors; `MakeSolid_3(shell)`.
- Sewing closure signal is `sew.NbFreeEdges() === 0` (not `IsNull`, volume sign, or BRepCheck). **Use a fresh `Sewing` instance per tolerance rung** — repeated `SetTolerance`+`Perform` on one instance crashes the module.
- Face split: `BRepFeat_SplitShape_2(shape)` → `Add_3(edge, face)` (edge lying on the face; `Add_1` takes an unbound sequence, `Add_2` a wire, `Add_4` a compound) → `Build()` (0 args) → `IsDone()` → `Shape()`: block.stp top face 6→7 faces, volume and area unchanged, halves 6 + 6. `BRepAlgoAPI_Splitter_1()` + `SetArguments`/`SetTools` (`TopTools_ListOfShape_1`, `Append_1`) + `Build()` gives the same with an EDGE tool; with a plane-FACE tool it cuts the solid in two. `BRepGProp.VolumeProperties2`/`SurfaceProperties2` return the integration *error estimate*; the value is `props.Mass()`. Shipped as the `splitFace` op (`edgeIds` or two `points` → one `MakeEdge_3` segment); the no-split guard is the **face count** (`collectFaces` before/after, like `unifySameDomain`) — an unchanged count returns the ORIGINAL handle with a `fail` diagnostic, never the rebuilt-but-identical shape — and buckets record the new `splitRegion` role.
- Features: `MakePrism_1(face, vec, false, true)` (Copy=false reuses the profile as the start cap), `MakeRevol_1`, `BRepOffsetAPI_MakePipe_1`, `ThruSections(true,false,1e-6)` (wire-based: consumes `OuterWire`, drops holes), `MakeThickSolidByJoin` exactly 9 args (needs ≥1 opening face), `MakeOffset_3(wire, GeomAbs_Arc, isOpenResult)` + `.Perform(d,0)`, `BRepAlgoAPI_Defeaturing` (0-arg ctor, `SetShape`/`AddFaceToRemove`/`Build`/`Shape`), `ShapeUpgrade_UnifySameDomain_2(shape, true, true, false)` (args are `UnifyEdges, UnifyFaces, ConcatBSplines`) → `Build()` → `Shape()`.
- Writers: STEP `STEPControl_Writer_1` → `Transfer(shape, AsIs, true)` → `Write(path)`; IGES `IGESControl_Writer_1/_2(unitName,0)` → `AddShape` → `ComputeModel` → `Write_2(path,false)`; BREP `BRepTools.Write_2`. XCAF STEP: `STEPCAFControl_Writer.Perform_2(doc, path)` (**`Transfer_1(...,"")` writes multi-file output with no geometry** — a real shipped defect). The `_1` stream overloads are unbound.
- **MEMFS paths: keep ≤10 chars** (`/o.step`, `/p.brep`, `/a.step`…). Longer paths make STEP/IGES write "succeed" then fail the read-back (`errno 44`).
- Face/curve classification: `BRepAdaptor_Surface_2(face,true).GetType()` compared **symbolically** against `GeomAbs_SurfaceType`; call the matching accessor (`Cylinder()/Cone()/Sphere()/Torus()/Plane()`) only after gating — a wrong accessor throws a **raw number**. Edge pcurve normal: `BRepAdaptor_Curve2d_2(edge, face)` → `GeomLProp_SLProps_1`. `BRepGProp` volume/area: use `src/brepGProp.ts` adaptive wrappers (`VolumeProperties2`/`SurfaceProperties2`, eps 1e-3); `LinearProperties` only on a single edge. Distance: `BRepExtrema_DistShapeShape` 0-arg ctor + `LoadS1/LoadS2/Perform`.
- `collectSolids`' `byId` map holds **raw handles**, not `{id, solid}` wrappers (wrapper → opaque `$$` error).

**Dead or misleading in this build (don't re-propose):** `HLRBRep_*` / `HLRAppli_ReflectLines` (binding works, drawing is worse than triangle adjacency); `ShapeFix_Shape/Shell/Wireframe` (only `ShapeFix_Solid`); `BRepExtrema_DistanceSS` and `Extrema_ExtFlag_MAX` (never compute the maximum); `MakeOffsetShape` on a **solid**; `BRepOffsetAPI_DraftAngle.Build()` (op wired, honestly skips); `MakePipeShell` rail wiring and loft start/end conditions (loft `guides` are a resampled fallback); `BRepAlgoAPI_Section` ctor; `IMeshTools_Parameters` / `BRepMesh_IncrementalMesh_3`; `GeomAPI_Interpolate` (splines are an approximating fit); `TCollection_ExtendedString` → JS string and XCAF **name/colour read** (assembly *structure* read works); `Interface_Static.CVal` / STEP unit setters (STEP unit label is a text patch); `StepData_StepModel` downcast; `oc.getExceptionMessage` (OCCT exceptions arrive as bare numbers); `GeomAPI_ProjectPointOnSurf` parameter accessors. `BRepMesh_IncrementalMesh_2(shape, lin, false, ang, true)` parallel is safe and faster. **`BRepMesh_IncrementalMesh_2` on a completely empty compound aborts the module** — `tessellateByGroup` returns `[]` when there is no sub-shape (a wire-only shape is fine).

**Gmsh facts:** gmsh-wasm 0.4.0 is the *same* Gmsh commit as 0.3.0 (`29726e7`, OCC 7.8.1; `General.BuildInfo` now names it) plus a `gmsh.view.*` namespace — so every Gmsh-behaviour finding below and in the roadmap carries over unchanged. **View-driven sizing (gmsh-wasm ≥ 0.4.0, verified call shapes):** only a **list-based** view can steer the background mesh — `view.add(name)` then `view.addListData(tag, "SS", nElements, data)` with per element `x1..x4, y1..y4, z1..z4, v1..v4` (`"SP"` with per point `x, y, z, v` works too and is what `MeshOptions.sizeField` ships: `addPostViewField` in `gmshSizingFields.ts`), then `field.add("PostView")` + `setNumber(f, "ViewTag", tag)` (`ViewIndex` fallback) + `setAsBackgroundMesh` (or as a member of the `Min` list — the `sizeField` route joins, never a second background call). A model-based `addModelData` view is refused by Gmsh ("Cannot use view based on current mesh for background mesh"), and `gmsh.clear()` removes every view, so add the view after the model is rebuilt and `view.remove(tag)` after `generate()` (a failing remove is swallowed — the singleton may already be reset). **The singleton persists *options* across `clear()` too:** `loadGeometryAndApplyOptions` sets `Mesh.MeshSizeFromPoints/ExtendFromBoundary/FromCurvature` explicitly every run (1/1/0 without a view, 0/0/0 with one) — a refined run otherwise poisons the next uniform one (measured 2735 → 2330). Shipped as `MeshOptions.sizeField` (headless `generate_mesh`/`export_mesh`; panel round-trips, no editor yet). OCC bounding boxes carry a 1e-7 padding (`getBoundingBox` of an axis-aligned edge at y=0 has `ymax = 1e-7`): compare with a tolerance ≥1e-5, never 1e-9. Default `Algorithm3D = 1` (Delaunay; the old Frontal workaround was an upstream stack-overflow fixed in 0.3.0; HXT works). `Mesh.SaveAll` must be forced `1` or physical groups filter the output. gmsh type 140 (hex-dominant trihedron connector) has no table entry on purpose; Kratos MDPA export refuses it by name. Gmsh's OCC importer drops free wireframe geometry (STEP round trip is lossy), and its STEP importer honors a declared unit.

## Ids, sidecars, persistence

- **Sidecars next to the source** (each: pure vscode-free `*Sidecar.ts` parse/serialize + `*Store.ts` fs I/O + `src/mcpSidecars.ts` node-fs twin, tolerant per-entry parse that drops bad entries, never the file): `.parts.json`, `.edits.json` (ops + `variables` + `bakedThrough`), `.mesh.json` (+ one-way generated `.geo`, never read back), `.view.json`, `.annotations.json`, `.planes.json`, `.layers.json`, `.scad-params.json`. Per-save `.save-journal.json` and `*.handoff.json` are transaction/export artifacts, not document state. Each store calls `assertNotDirty` (refuses to clobber an unsaved editor buffer). Adding a field to a model object means copying it in that model's `clone()` (`AnnotationsModel`/`PartsModel` each silently dropped one once).
- **Version bumps:** additive fields need none (`layout`, `panes`, `collapsedPanels`, `bookmarks`, `sidebarWidth`, `clip.normal` were all additive — keep `axis` beside `normal` so an older build doesn't null the whole clip).
- **Entity ids are deterministic and positional:** B-rep `solid-N`/`face-N`/`edge-N`/`point-N` by `TopExp_Explorer` order; mesh `node-N` / `node-N/face-K` by traversal order — **never a THREE `uuid`**. Mesh "surfaces" are computed facets (`meshFacets.ts`, ~15° coplanar, ≤512 facets else kept whole + BVH). Headless mesh ids are `mesh-component-N`/`mesh-triangle-N`/`mesh-vertex-N`/`whole-model` — deliberately *not* `node-N` (different object model). Plane/layer ids are **allocated and never reused** (persisted counter / max+1).
- **Shared enumerators must stay in lockstep:** `edgeEnumeration.ts`'s `enumerateEdges` is the single edge list (display `extractEdges` and op-resolution `collectEdges`; `EDGE_DEFLECTION` is a fixed constant — varying it by quality would repoint `edge-N`). `tessellateByGroup`'s free-face pass and `occtOperations.collectFaces`/`addFreeFacesOf` are **duplicated and must stay in lockstep** (sketch faces are an extra `"Sketches"` group). Vertices likewise via `collectVertices`/`extractVertices`.
- **Id drift + rebinding:** topology-changing ops renumber ids. `entityRebind.ts` (pure greedy nearest-neighbour on bbox centre + measure, per kind, tolerance `1e-3 × bboxDiagonal`) remaps Parts/annotations/layers; `rebindPartsAcrossOps(oldOps,newOps,…)` steps per op for pure append/truncation but does **one direct whole-shape match** for any other change (stepping a mid-list removal drops entities that never moved). Rigid transforms are excluded (`TOPOLOGY_CHANGING_OPS` gate — a copy-transform "produces" every face). `rebindPartsAcrossSave` does a two-byte match for save-time rebinding. Planes store resolved vectors and are never rebound. `maybeRebindParts` runs on `apply_edit_ops`/`run_parametric_script`/`remove_edit_op` and reports in `warnings`. Stored queries (`Part.selector`, per-op `targetQueries`, `resolve_selector`/`synthesize_selector`) re-derive ids from build-time buckets (`opBuckets`, valid only against that op's own state) and freeze on any guard failure; they resolve inside a **sequential fold** and disable append-reuse in `loadBRepCached`.
- **Watermark / tail replay:** `bakedThrough` = number of ops already baked into the source. `readEditsResolved` returns tail ops for replay plus `fullOps` for display/persist; every `writeEdits` must thread the watermark. Kernel `opOutcomes`/`opBuckets` are tail-relative and rebased onto full-history rows in `handleBRep`. `remove_edit_op`/undo/jump/clear refuse to cross the save point (webview `EditsModel.savePoint`, locked 🔒 rows). Mesh sources replay only `ops.slice(savePoint)`.
- **Save-in-place** (`bakeTailToSource` / `bakeMeshToSource` / `save_model`): pre-check `assertNotDirty(edits)` → modal confirm → bake → one-deep `<model>.bak` (first save of the session) → temp sibling + rename (`expectOwnSourceSave` suppresses the source watcher once) → watermark write → B-rep: two-byte rebind → reload. A watermark-write failure rolls the source back. Every save is wrapped in a `<model>.save-journal.json` transaction (`saveJournal.ts` pure policy + `saveRecovery.ts` injected-fs choreography; recovery `finish`/`discard`/`ask`; restore offered only if `sha256(.bak) === preSaveSha256`; after `finish` call `revisions.noteSynced("edits")`; restore runs inside `withSourceWrite`). A B-rep journal is written by both `bakeTailToSource` and headless `saveModelTool`; recovery runs before edit replay on open/load. A recovered B-rep `finish` advances the watermark but does **not** redo the save-time id rebind (the pre-save bytes are not guaranteed to be the one-deep `.bak` on a later save), so its message tells the user to verify Part/annotation/layer highlights. glTF/meshio/csg/scad have no same-format writer and are never dirty. `exportTargetsFor(route, allowSameFormat)` is opt-in; headless export paths keep excluding the source's own format. Hot-exit backup: `customBackup.ts`.
- **External-change reconciliation:** one `FileSystemWatcher` per watched file, debounced 300 ms, and **content-compared** (`JSON.stringify` equality) so the extension's own writes never loop. The CAD source is unconditionally external. Conflicts (disk change while a local edit is pending) prompt Reload / Keep mine via `sidecarRevision.ts`; `guardedAutosave` re-fingerprints right before writing (residual TOCTOU stated). `.scad` dependency watchers come from `onScadDependencies`.
- **MCP optimistic revision guard:** `expectedRevision` is injected/stripped by the `registerTool` decorator in `mcpServer.ts` (`REVISION_GUARDED_TOOLS`); check+handler+write run under a per-(model, kind) promise-chain lock; stale → `stale-revision`. Per-process only.
- **Preprocess archive** (`preprocessArchive.ts`): `manifest.source` must be a bare filename (`isSafeEntryName`), zip-bomb caps via `unzipSync({filter})`, SHA-256 `checksums`, `minimumReaderVersion` gate, restore cross-checks source vs destination format; `.geo` is no longer packaged.

## Edit ops (`src/editOps.ts`, `occtOperations.ts`, `webview/meshEdits.ts`)

- **One tolerance gate, `validateEditOp`** (sidecar parse and every incoming op pass through it). Bad op → dropped, never a crash. Every plane/direction vector goes through `asNonZeroVec3`. For a new op kind ship the panel form + apply wiring + `buildOpForPanel` case + `tintForPanelOp` entry + `opCatalog.ts` button + TikZ icon + `OP_PARAM_DOCS` + doc in the **same change** (a catalog button without a form is a dead surface; `opCatalog.test.ts` locks 1:1 coverage; `opCommands.ts`' `COMMAND_TABLE` is locked 1:1 to the catalog).
- **Engine split:** B-rep ops fold in the host (`applyEditsBRep`), mesh ops in the webview (`applyEditsMesh` over a pristine clone, rebuilt every edit), and headless via `bakeMeshEdits` in the worker (same loaders: `webview/meshObject.ts`, so `node-N` ids match). `BREP_ONLY_OPS` are skipped on meshes. Hole ops (`addHole`/counterbore/countersink) run on both — in `applyEditsMesh` they must dispatch **before** the `startsWith("add")` primitive branch and never bump `prim-K`; mesh patterns tag `pattern-K`.
- **Mesh booleans/holes run through `manifold-3d`** (`webview/manifoldBoolean.ts`; init in `manifoldBrowser.ts` — awaited before `loadUrl`/`loadMeshBytes` because `applyEditsMesh` is synchronous — and `manifoldNode.ts` for the worker's `bakeMeshEdits`, which reads `dist/manifold/manifold.wasm` as `wasmBinary`). `three-bvh-csg` remains the fallback when manifold is not ready or refuses an operand (`ManifoldRefused`: open, non-manifold or inside-out; reported through `report`). Manifold's constructor can throw OR return a non-`NoError` status, so check both. Operands are welded on position (a loader soup is unindexed) and the result is rebuilt with `toCreasedNormals`. `MESH_MANIFOLD_MAX_TRIANGLES` (500k) is measured, not borrowed. A single-mesh source has the mesh AS the root: `installCsgResult` edits it in place — adding the result as a child used to leave the unedited mesh displayed and exported. The `webview` build marks `node:module` external (manifold's Node branch).
- **Graceful skip, never throw, never silent:** an unresolved operand / builder throw / `IsDone()===false` returns the shape unchanged **and calls `fail(diagnostic, hint)`**; `applyEditsBRep` also records an identity-compare backstop. `OpOutcome {index,kind,applied,diagnostic?,hint?}` flows to `load_model`/`apply_edit_ops` warnings and ⚠ history rows. Slice `opOutcomes` to the current call's ops before counting `applied`.
- **Parametric variables:** `exprs` is an annotation, the numeric field is the last-good cache; resolution only at `parseEditsJson` and the webview resolve-on-read (`currentResolvedOps()`) — keep resolve-on-read, don't patch stored ops. Field paths are an identifier plus ≤2 numeric indices (so thin `thin`/`thinOuter` are flat). A variable may reference only variables above it. Failures freeze, never crash. Same annotation+cache pattern for `planeId` (`planeRefs.ts`), `pointRefs` (curve ops; strict re-anchor-or-skip, resolved *in the fold*), profile-on-plane placement. Repeat/script ops are fully baked (`exprs` stripped); `refreshOpCaches` keeps plain steps live.
- **Operand conventions:** transforms act on whole solids; `align` stores a resolved coordinate; patterns count the original (`count` total) and copy via `Transform(copy=true)`; creation ops append `compound(existing + new)` (`center` = geometric centre for box/sphere/torus, **base** centre for cylinder/cone/prism). Profile-op sketches are flat faces consumed by extrude (Copy=false) but **not** by thin/pick builds. Sweep-family profile is a `face-N` **or** an edge set (`profileEdges`; closedness from vertex degree); open profile requires `thin` and refuses `thinOuter`; `thin` wall = `MakeOffset` band, an over-large offset returns an *empty compound* (check `ShapeType()`); `pick` selects regions of a multi-loop profile; `guide:true` marks construction geometry (dimmed, refused as an operand for 6 profile ops, host + webview). `mirror/splitByPlane/section/draft` take `planeId` XOR `midplaneFaces` XOR inline pair. `defeature`, `wrap` (develop-and-sew thickening; targets are analytic params), `rib`, `drillCut`, loft `guides`: see their `OP_PARAM_DOCS` entries; `draft` and loft end conditions are kernel-blocked.
- **`unifySameDomain` (parameter-free, whole-model, B-rep-only, topology-changing):** `QUERYABLE_OPERAND_FIELDS.unifySameDomain` is `[]`, buckets record the generic `produced` role. `Build()` returns a new shape even when it changed nothing, so "nothing to merge" is decided by the **face count** (`collectFaces` before/after) — an unchanged count returns the ORIGINAL handle with a `fail` diagnostic (`applied: false`), never the rebuilt-but-identical shape. Parts rebind through the existing path; a Part on a split half is **dropped with a warning** (merged centroid is far outside the `1e-3 × bboxDiagonal` match tolerance), never repointed.
- **Coincident points** (`addPoint.coincident`): detection runs **in the fold** (`addWireframePrimitive`, same `pointMatchTolerance` as `resolvePointRefs`), never in the webview (whose `findCoincidentPoint` pre-check is advisory). `reuse` returns the shape unchanged **but is applied**: it sets `OpOutcome.note` (via `fail.note`), which also exempts it from the identity backstop — don't "fix" it into a `fail`, and never remove the op (every later op index and `pointRefs.opIndex` would shift). Notes are informational (`applied` stays true) and ride `opOutcomeWarnings`; replay re-emits them for persisted ops. **Curve endpoints typed raw** (`addLine`/`addThreePointArc`/`addPolyline`/`addSpline`/`addBezier`, `COINCIDENT_CURVE_KINDS` + `curveEndpointSlots`; `point-N` slots are skipped — already shared) use the same detection with `coincident` on the op. Without sharing, every curve builds its own `TopoDS_Vertex` and `collectVertices` dedupes by `IsSame`, never by coordinate, so a coincident endpoint is a twin `point-N`. `reuse` snaps the coordinate and **shares the existing vertex**: `BRepBuilderAPI_MakeEdge_2(v1, v2)` for lines/polyline segments, `MakeEdge_29(curve, v1, v2, t0, t1)` for arc/spline/Bezier (trimmed between the vertices); a refused share falls back to an independent endpoint with a note. `addArc`/`addEllipseArc`/`addHelix` have no typed endpoints and take no choice.
- **Primitives recognition / decomposition / fit:** `recognize_primitives` (`primitiveReport.ts`, exact face-count signatures, SDF residual from tessellation — compare `fitResidualFrac`, never zero, Float32 noise floor), `decompose_to_primitives` (`primitiveEmit.ts` → variable-bound ops, new file via empty-compound `buildPrimitivesFile`), `fit_mesh_region` (pure, WASM-free least-squares plane/cylinder/sphere; cylinder axis from normal covariance; `store` opt-in).
- **Live preview** is a speculative replay with a separate `::oppreview` cache key, never enters the op stack, cancelled on form switch/selection change/Apply/rebuild; mesh preview is client-side.

## Meshing and export

- **Gmsh generate** (`gmshService.ts` `populateMeshedModel` is the one dispatch point for generate/export/MDPA): B-rep sources re-export STEP via `exportBRep` (reflecting edits) then `importShapes`; mesh sources send STL (webview-serialised, or headless via `meshSourceInput.ts`). `engine: "ftetwild"` merges fTetWild's MSH 4.1 tets into the same Gmsh model so every downstream reader works unchanged (`engine: "octree"` takes the same seam — see its bullet under meshio++ import); **downgraded to Gmsh with a warning** for B-rep sources or non-3D; `exportGeoUnrolled` refuses it. Any single-pass `MeshOptions` field must be added to `validateMeshOptions`' terminal return literal (it builds field by field).
- **Field adaptation** (`MmgOptions.adaptField`/`adaptStrength`, inside `meshioService.remeshMesh`; file mode, linear tets only): the ZZ indicator from `estimateError` (read `cell_data["error:zz"]` per BLOCK — only tetra blocks are concatenated, in `prepareMmgMesh`'s order) → `adaptSizing.sizeMapFromIndicator` → `MmgMesh.vertexSizes` → `setSolSize(mesh, met, MMG5_Vertex, np, MMG5_Scalar)` + `setScalarSols`; the one field returns via `conservativeInterpolate` (output `point_data`, Float64) and the report's `conservation.relError` is computed with `lumpedIntegral`. `two-material-tets.med` has 2 tets (uniform indicator) — use a Gmsh-meshed `block.stp` for anything density-related. A tensor metric works but was not worth shipping (≈13 % fewer cells at matched error).
- **Parts → mesh** (B-rep only): `gmshPartsMap.ts` resolves part ids to Gmsh entities **geometrically** (bbox-centre match, `1e-3 × diagonal`; `importShapes` order isn't trusted) → physical groups; `meshSize` → `Constant` field; `meshGrading` → `Distance`+`Threshold` (volume anchors converted to boundary surfaces via `getBoundary`; skipping that degrades silently); all fields combine in one `Min` background field. Free wireframe `point-N`/`edge-N` that didn't correlate are created with `occ.addPoint/addLine` (`gmshEmbed.ts`; **never `mesh.embed`** — it degrades quality; straight-line endpoints read from the curve, not Float32 polylines; curved free edges warn). `applyPartsToGmshModel` touches both kernels, so an OCCT abort there also resets Gmsh. STL sources get only a one-off size override when exactly one part has `meshSize`.
- **Anisotropic boundary layers** (`Part.meshBoundaryLayer {wallSize, growthRatio, thickness, quads}`; pure `validateMeshBoundaryLayer`/`boundaryLayerPlan`/`boundaryLayerAlgorithmProblem` in `meshOptions.ts`, field in `gmshSizingFields.ts`'s `addBoundaryLayerField`): a Gmsh `BoundaryLayer` field on the Part's `edge-N` curves, **2-D B-rep generates only** (a 3-D generate ignores it with a warning; no 3-D route exists). It is registered by its **own `setAsBoundaryLayer`** and must never join the shared `Min` background list; it coexists with that background in either call order (measured; the roadmap's earlier "background voids the layer" did not reproduce). Use the canonical option names `Size`/`Ratio`/`Thickness`/`Quads`. `FanPointsList` = the unsigned points of `getBoundary(curves, combined: true)` (flat dimTag array — a nested `[[1,t]]` returns nothing), so a split wall does not fan at its interior joint. **Algorithm gate (`loadGeometryAndApplyOptions`, before any gmsh work):** only Automatic 2 / Delaunay 5 / Frontal-Delaunay 6 / Frontal-Delaunay-for-Quads 8 (and MeshAdapt 1 without recombination) carry a layer; MeshAdapt + `RecombineAll` and Packing of Parallelograms 9 **abort the WASM module**, BAMG 7 throws, and 3/11 silently drop the layer — so those are refused up front. `wallSize`/`thickness` scale with the export unit (`scalePartsMeshSizeForUnit`), the ratio never. Achieved rows are measured after a 2-D B-rep generate by the pure `boundaryLayerMeasurement.ts` (planned rows from `boundaryLayerPlan`, achieved min/median and coverage over sampled wall stations), reported as `MeshResult.boundaryLayers` / `HandoffFacts.boundaryLayers`, appended to the panel's layer row, and warned about when any sampled station falls short; the measurement is read-only and never changes the mesh. It is 2-D only, like the layer itself.
- **Periodic pairs** (`MeshOptions.periodic`, Part names + `translation` = master − slave): `gmsh.model.mesh.setPeriodic` takes the NEGATED translation (its affine maps master→slave) and runs in `applyPartsToGmshModel` after Parts resolve; each Part must resolve to exactly one surface. Option state from an earlier hex-dominant run breaks periodic matching, so every generate re-sets every option. Kernel-blocked/rejected from the same probe batch: `healShapes` deletes `daratech.stp`'s volume; gmsh type 140 does not close the volume (see roadmap Non-goals).
- **Element tables:** `gmshElementTypes.ts` is the single source for strides, boundary faces and gmsh→Kratos node permutations (derived against the live WASM). `mdpaWriter.ts` is hand-written (orientation via signed volume; geometries mode shares one id space; 2D exports use planar names; quadratic prism18/pyramid14 truncate); Kratos block names are confirmed against Kratos core registration.
- **Export formats** are one registry (`meshExportFormats.ts`, `via: gmsh|mdpa|meshio`, optional `companion {extension, linkage: referenced|sibling}`) used by host, webview and MCP. Gmsh can't write CGNS/MED/XDMF here → meshio++ bridge (`exportViaMeshio`, takes Gmsh's MSH 4.1 text). Excluded because they fail on `Mesh.SaveAll` shapes: vtp, vti, h5m, ugrid, tecplot, ansys, freefem, dex, ip, mff, mfm.
- **Export units:** a real geometric scale. BREP: `scaleShapeForExport` about the origin. STEP: scale then **text-patch** the unit declaration (`stepUnitPatch.ts`; patches *every* `GLOBAL_UNIT_ASSIGNED_CONTEXT`). IGES: `IGESControl_Writer_2(igesUnitName(unit),0)` scales internally (don't also scale). Mesh targets scale a clone. 3MF writes a matching `unit=`. A correctly labelled STEP/IGES reopens at the same real-world size. Meshing-input STEP uses `labelStepUnit:false` (Gmsh honors the label and would undo the scale). The FE-mesh export unit scales geometry **and** `sizeMin/sizeMax/meshSize/meshGrading` proportionally; Generate is always native mm. Display unit (`#vc-unit`) is presentation-only.
- **Deterministic exports** (`deterministic: true`): STEP normalised by `deterministicHeader.ts` (timestamp, translator counter, wrapped statements — unwrap before rewriting); IGES/BREP already stable; mesh formats via `deterministicMesh.ts` plus `Date.now` pinned to 0 around the synchronous meshio `convert` (fixes HDF5 containers); handoff manifest drops `createdAt`. Every STEP write is checked for `NaN` and redone from a fresh read (refuses after 3). Named-Part STEP is not byte-promised.
- **XCAF:** read gives assembly structure only (separate `STEPCAFControl_Reader` parse; leaves correlated to real `solid-N` by `rebindEntities`, all-or-nothing bijection else flat). `solid-N` order is never changed by it. On the interactive path the tree is posted *after* geometry (`deferAssemblyTree`, `resolveAssemblyTree`, `upgrade:true`). Write gives names + assembly structure only (colour write is **not** adopted — see roadmap).
- **Tessellation quality** (`draft/standard/fine`, `tessellationQuality.ts`): `standard` = linear 0.1 / angular 0.5. Public boundaries take the **name**; the interactive setting is re-read each `handleBRep`; headless tools default `standard` (drawings default `fine`).
- **Quality gate** (`check_mesh_quality` / FE Mesh gate row; `meshQualityGate.ts`): meshio++ `checkQuality(mesh, require, maxInverted, maxDegenerate)` over Gmsh's MSH text (`readMesh(...,"gmsh")`, ≤10-char MEMFS path). The threshold text is the **caller's**; the result is facts. A clause's `evaluated` can be `0` (meshio++ still says `passed`) → `vacuous`. `inverted`/`degenerate` are always appended as clauses (worstCell `-1`). `@ N%` sets `maxFraction`. A bad spec/unknown metric throws a plain message (not an abort). The panel gates the host-cached MSH text of the last panel generate (`lastMshText` in `provider.ts`), not a regeneration.
- **Mesh → B-rep:** `check_mesh_health` is facts-only (per-component, OCCT sewing ladder `1e-6…1e-2`, 50 000-triangle ceiling; opt-in `autoDecimate` to ~1 000 triangles via `mmgCoarsen.ts`'s `coarsenStlBoundary` — mmgs with `hausd` (a fraction of the bbox diagonal) bisected in log space, because mmgs takes a deviation bound, not a triangle target; the shipped QEM `decimate` heals to volume 0 and meshio++ clustering `remesh` never closes, so do not swap either back in. mmgs `hausd` is ABSOLUTE source units in the raw API: the earlier negative probe passed 1 % of the diagonal as if it were the useful value and over-coarsened to 391 open triangles. The report carries `decimated.{method,hausd,hausdFraction,volumeDeltaPct}`; promote still volume-checks). Winding: the count comes from `featureEdges(mesh, 180, false, false, false, true).numInconsistent` (inconsistent class only, no sharp-edge scan); `surfaceWatertightCheck` is kept for the other counts and a disagreement between the two is **reported** (`inconsistentDisagreement`), never silently resolved. Each component also carries `inconsistentEdges` (welded-vertex index pairs — `componentMesh` returns the local→welded map because line cells index the input mesh's own points) + midpoints, capped at `MAX_REPORTED_INCONSISTENT_EDGES = 200` with the true total in `inconsistentPairCount`. `feature:kind` arrives as `BigInt64Array` (meshio++ ≥11.2 integer rule) — compare through `Number()`. `meshTopology.ts` deliberately has no winding check (sorted-pair adjacency discards orientation). `promote_mesh_to_brep` writes a **new** file (never reclassifies the open mesh). **`mergeFacets`** (`meshFacetMerge.ts`, opt-in; MCP param + Mesh Health "Merge facets" checkbox): one planar face per near-coplanar facet instead of one per triangle — a facet merges only if every vertex is within `1e-5 × bboxDiagonal` of its best-fit plane AND its boundary traces to exactly one CCW outer loop plus CW holes (each a simple cycle), else its triangles stay individual, so a curved surface is never flattened (the angle alone is NOT the guard: a 15° tolerance chains a 32-gon prism's 11.25° sides into a non-planar facet that will not sew closed). The 50 000 ceiling then applies to the *faces left* (merge accepts ≤300 000 triangles). The options argument is passed to the pipeline **only when merging** (a trailing `undefined` changes `toHaveBeenCalledWith` arity and the IPC bytes). `check_mesh_health` stays per-triangle. `repair_mesh` = fTetWild boundary. `fit_mesh_to_cad` (`meshFitCad.ts`) is the analytic sibling of promotion: meshio++ `fitCad` over the same host weld (`parseToWeldedMesh`) → `segment` → `fitPrimitives` front end as `segment_mesh_surface`, replacing each patch with a trimmed analytic face (plus fillets/blends/chamfers/threads/freeform B-splines) and sewing/checking with the FULL artifact's OCCT — closed, consistently wound skin required (a dirty one throws upstream's own open-edge error), STEP (AP214) only, no format/unit pickers in the panel, and `cadJsonPath` writes the B-rep side channel for the `iga_*` tools. One-shot like promotion; never touches the source.
- **meshio++ import:** every meshio format funnels through meshio++'s STL boundary so it inherits the whole mesh pipeline. Guards: `meshioBoundary.ts` refuses a boundary whose extent is smaller than the source's (EnSight `.case` is therefore *not* routed — silent wrong geometry); quad boundaries are triangulated by `convertCells(simplexify)`; `LOSSY_METADATA_FORMATS` (med/cgns/gid) read metadata via a full `readMesh` because native header scans under-report; region→Parts correlation uses `cell_data["surface:parent_cell"]` (cell regions only; auto-created only into an empty parts sidecar, `node-0/face-K` ids need the same region-gated facet split reproduced in the webview, only while the edit list is empty). Multi-file sources stage companions (`meshioCompanions.ts`: XDMF `.h5`, stem pairs, GiD `.post.res`). Ambiguous extensions (`.msh/.inp/.bdf/.rst`) get a one-line caveat (`.rst`: ReStructuredText). Nastran decks get `BEGIN BULK` prepended on read (`nastranDeck.ts`). OpenFOAM is path-based (`convertFoamCaseToStlBoundary`, geometry only). libMesh (17.2.0) routes `.xda`/`.xdr` plus the `.xda.gz`/`.xda.bz2` compressed pairings (bzip2 = full artifact only; `.xdr.gz`/`.xdr.bz2` deliberately unclaimed — no fixture) and exports plain `.xda`. Kratos CAD JSON (`.cad.json`, 17.2.0) is the one format whose cells ARE the surface — the bridge linearizes in place (extractSurface would return free edges); its NURBS side channel never crosses the IPC boundary (`meshIga.ts` stages + reads + ops in-worker: `CadJsonInfo` carries `BigInt64Array`) and the `iga_*` tools also accept STEP/IGES (same side channel on those reads; refine always writes CAD JSON). meshio++ 17.3.0 adds six two-way formats routed on exact upstream format names — `tecplot` (.plt), `xplt`, `medit`+`.meshb` (the binary variant rides the ALREADY-ROUTED medit id: one reader, content-sniffed binary), `marc_t19` (.t19), `abaqus_fil` (.fil), `ansys_rst` (.rst), `lsdyna_d3plot` (.d3plot; single-file writes only, family split is a size cap) — with the `.plt`/`.xplt`/`.meshb` writers dropping 0-D vertex blocks and the results writers merging per cell type (verified facts; corpus export+fixture rows pin each round trip). **Two boundary traps in `convertToStlBoundary` (`meshioBoundary.ts`):** native `convertSurface` writes only the *triangular* boundary faces and silently drops quad ones, so a mesh with a wedge/pyramid/hexahedron/polyhedron cell (`hasQuadFaceVolumeCells`) skips it for `extractSurface` + `simplexify` — a wedge box read as volume 8 instead of 24 and the extent guard cannot see that (the triangular caps touch every vertex); and `extractSurface` on a **shell-only** mesh (`isSurfaceOnlyMesh`, e.g. Nastran CQUAD4/CTRIA3) returns its free *edges*, so those cells are linearized in place like `cad_json` (and a `convertSurface` fragment that fails the extent check is discarded rather than refused). Document-derived strings (region names etc.) go through `untrustedText.ts` (`clean`/`envelope`).
- **meshio++ `octree` (17.8.0) — shipped as `engine: "octree"`** (`octreeService.ts`; panel select + `octreeMaxLevel`/`octreeSnap`; docs in `doc/gmsh-integration.md#octree-engine`). Runs on the meshio++ singleton, so no new `Pipeline` function. Traps: the call is **positional** (`m.octree(skin, null, 0, maxLevel, null, undefined, undefined, 3, undefined, "face", "inside", undefined×5, "templates", snap)`; `dimension` is the 8th argument); **`transition: "templates"` only** — `"polyhedra"` emits `polyhedron` blocks the MDPA writer refuses; **never `extractSkin` on the result** (faults "memory access out of bounds" on a level-5 bull mesh); volumes must be measured orientation-free (grid parity), a single-interior-point flux overcounts concave geometry ~2x. **MSH 4.1 merge: every cell-class block goes on the ONE volume entity (dim 3, tag 1)** — without `$Entities`, `gmsh.merge` only creates entity 1 and a block on entity 2 fails with "Unknown entity 2 of dimension 3". meshio++'s hex/pyramid/tet node order already matches Gmsh's reference cells (probe `meshio-octree-orientation.ts`: all cells positive), so **no reorder**; the exact-volume checks (`block.stp` level 4 = 3522 cells = 1372/542/1608, volume 60.000; `cube.stl` = 1000) are pinned in `mcp:smoke`. Snapped boundary cells on a curved skin can be near-degenerate (bull level 4: min `minSICN` ≈ 0) — facts for `check_mesh_quality`, never "fixed" here. No Parts/physical groups (no face correlation); `octreeUnsupportedOptions` is the one place that decides refuse (elementOrder 2, non-simplex shape, `periodic`, `sizeField`) vs warn (optimizer pass, Parts); `runMeshSweep` and `.geo_unrolled` refuse the engine by name. A B-rep source tessellates on host OCCT (`brepSkinStlBytes`, `fine` preset) inside `populateMeshedModel`. Not in the first increment: boundary layers, sizing-field/curvature refinement, 2-D quadtree, Part preservation.
- **OpenSCAD:** `.csg` parses to an AST and builds an opaque base shape with live handles (`csgImport.ts`/`csgModel.ts`; colours → Parts via `csgColorParts.ts` on first open into an empty sidecar and only with no replayed ops); `.scad` converts WASM-first with `scadService.ts` + worker-side `scadWasmService.ts` (bundled `@loumalouomega/openscad-wasm`, Manifold default, `convertScadViaWasm` Pipeline function; byte-identical to the binary on every committed fixture; `import()`/`surface()`, missing includes and over the 20-file/1 MB staging caps decline with `ScadWasmFallbackError` to the user-installed binary — cwd = source dir, 120 s timeout, argv not shell — and any other WASM failure surfaces, never silently retries the binary; conversion cache validated by dependency hashes, `-D` overrides validated, stderr parsed/capped/enveloped; no agent-supplied binary path). Worker errors lose their class across `kernelIpc` unless `name` is preserved (`kernelWorker.ts` sends it, `kernelClient.ts` restores it) — the host falls back only on `name === "ScadWasmFallbackError"`. The wrapper renders fresh per call (no shared Emscripten instance to corrupt); `resetScadWasm()` clears the cached module/bytes after an abort, like every other kernel.
- **glTF:** pure host parser (`gltfParser.ts`) welds internally; compressed files are pre-decoded in the worker into reserved `decoded:` buffer keys (`gltfDecode.ts`, `gltfInflate.ts` for the headless bake); a required-but-undecoded extension throws. 3MF is **display-only** (host can't parse; every host geometry consumer refuses it by name; `DISPLAY_ONLY_MESH_FORMATS` drift-guarded). OBJ `.mtl`/PLY/3MF colours are webview-only (`nativeColor.ts` stash is a `WeakMap`). 3MF: `3MFLoader` emits one mesh per distinct colour and a plain-white `Loader.DEFAULT_MATERIAL_NAME` fallback that must NOT be marked native (it would shadow Part colours); the writer reads `userData.baseColor`, never `material.color`, and treats the theme default as "no colour" so an uncoloured export stays byte-identical to a geometry-only one; the declared unit seeds `#vc-unit` through `userData.declaredUnit`. Collada (`.dae`) is the same display-only, plus import-only (no writer, never an export target): `ColladaLoader` multiplies the scene by the raw `<unit meter>` (metres; `NaN` if malformed) and rotates `Z_UP` to Y-up, but `Viewer.setModel` owns `rotation.x` and the viewer is millimetres — `loadDae` wraps the scene in a fresh Group, **resets the scene rotation and scale** and applies `colladaMmPerUnit` (`colladaUnits.ts`), and `convertColladaMaterials` clears the loader's magenta `DEFAULT_MATERIAL_NAME` fallback and its unnamed plain-white default `MeshPhongMaterial` (neither is a file colour). Textures are ignored. AMF (`.amf`) is the same display-only, import-only shape, but `AMFLoader` ALREADY scales to mm from `<amf unit>` — never rescale it (`amfUnits.ts` only seeds `#vc-unit`); `parse` returns `null` for a non-`<amf>` root (check it), a failed unzip is swallowed and later throws a `TypeError`, and its `DEFAULT_MATERIAL_NAME` fallback (0xaaaaff) is shared by a mesh-level `<color>` clone, so `convertAmfMaterials` clears it by colour, not name alone. `package.json` `customEditors` selectors and the open-dialog filter in `provider.ts` are hand-copied and **unguarded** — a new format needs both.
- **Drawings:** silhouettes and hidden-line removal are triangle-based (`silhouetteEdges.ts`, `hiddenLineRemoval.ts`: exact closed-form depth test, projection centred first for Float32); sheets (`drawingSheet.ts`) keep scale in real mm (no unit param), draw each pinned dimension once, DXF is Y-up (Y negated once at the write boundary). `"svg"` is deliberately **not** a `CadFormat` (would register `.svg` as an editor selector).

## Analysis and interaction features (invariants only)

- **Units:** OCCT's STEP/IGES readers already convert every shape to mm, so nothing in the pipeline needs converting; `lengthUnits.ts` is the one factor table. Detected source units (`stepUnits.ts`/`igesUnits.ts`, text scans — pick the unit in `GLOBAL_UNIT_ASSIGNED_CONTEXT`, not the first `LENGTH_UNIT`) only seed the display selector. Moments of inertia are about the **centroid** and left unconverted. Volume is computed only for whole model / `solid-N`, never `face`/`edge` (open shells give plausible wrong numbers). Mesh mass properties share `triangleMassProperties.ts` and carry a `watertight` flag.
- **Compare Models** is a report, not a merged scene. Greedy nearest-centroid match (tolerance `1e-3 × larger bboxDiagonal`) always ships the raw `centreDistance`/`volumeDeltaPct`, never a binary verdict. Sources are a `CompareSource` union (brep/stl/obj/ply/gltf); a mesh side is baked through the worker's `bakeMeshEdits` (falls back to the raw file with a warning). A meshio-only side is converted to its `meshioBoundarySide` welded STL boundary and reported in `sides` as `surfaceDerived` with its region count and watertight flag; its pending mesh edits are not baked. Snapshots are opt-in and degrade to a warning.
- **Transform gizmo** is a live preview only: attached to a permanent geometry-free proxy; the proxy's transform *is* the delta; per-target bases are captured fresh at every drag start; preview is cancelled on form switch **and** selection change **and** before commit; Apply is the only thing that pushes an op. Snap: grid rounds the shared delta once; point-snap runs per target (candidates are `point-N` sprites only). For exactly **one** target the form's `vec` is the **snapped delta** (`snapped - base`), so Apply commits the position the preview showed; a **multi-target** drag stays preview-only because one `translate.vec` cannot carry a different delta per target (the Move form hint says so). Three's `dragging-changed` event is generated dynamically by `defineProperty` (not a source literal).
- **Annotations** (`Annotation` is shaped as an `EntityIdBag` so rebinding is free): the measured text/anchor/`linePoints`/`tolerance.measured` are frozen at pin time; "detached" and out-of-tolerance are *derived* at display time (`Viewer.hasEntity`, `toleranceBand.ts`), never stored. Dimension glyphs share one pure `computeDistanceGlyph` between the 3D overlay and SVG/DXF baking. `note` annotations have no line/band. `check_tolerance` reports facts (`withinTolerance`), not a verdict.
- **Parts vs layers:** Parts drive meshing (names, sizes, physical groups); layers drive visibility, lock and drawing groups, and meshing never reads them. Lock refusals live at entry points (`lockedOperandForOp` in `apply_edit_ops`/scripts and the webview's `buildOpForPanel`), not in replay. Layer visibility composes with Part hide/isolate in `applyVisibilityState()` and is persisted per layer; hide/isolate state itself is session-only and stored as the *group id*, not expanded leaves.
- **Selection:** filters/groups reuse the registry in `selectFilters.ts` (the context menu supplies the clicked entity's value as the argument; reference-driven groups live in `selectionGroups.ts`); a group matching only the clicked entity is dropped. Hover → tooltip (webview only); selection → inspector card (one host round trip) — `getEntityFacts` has no shape cache, so never drive it from hover. "Mentioned by op N" wording, never "used by" (ids are positional). Entity facts for Copy reference are cached only until the next op-list change. Copy reference's stored query is attached only for faces in the **last** op bucket (`producingBucketFor`): bucket ids are valid only against that op's own state, so an earlier bucket's id may already be renumbered and a query synthesized for it would name the wrong face. Its synthesize requests use a separate `ref-` requestId waiter map, so they never consume the pin-as-query latch.
- **Selector synthesis / classification buckets / pin-as-query:** the panel owns only bucket coordinates; synthesis is server-side and accepted only on exact re-execution plus ~0 `centreDistance`; the query row refuses non-face or multi-face picks up front (no joint induction exists).
- **Clash / BOM / hole table / passages / deviation / budget / prep report / batch export / handoff manifest:** all reuse the same kernel functions as their MCP tools so panel and tool cannot disagree; budgets and caps (`maxPairs`, `maxBooleans`, `MAX_SWEEP_RUNS`, triangle ceilings) are reported as partial results, never silently truncated. Part-name → solid resolution lives in the tool layer; the kernel is Part-ignorant. Sweeps/batches take an `isCancelled` predicate (not an `AbortSignal`) so the module stays Node-free; a cancelled run yields no row and `applyIndex` is not honoured.
- **Printability** (`printability.ts`, `triangleRay.ts`, `printabilityHost.ts`, `check_printability`): facts only — `notChecked` rules are `checked:false`, never passed; wall thickness is SAMPLED (deterministic inward rays through a global pure grid caster — `three-mesh-bvh` stays webview-only) and support volume is an upper bound. A face exactly at the overhang limit is NOT an overhang (strict compare); a flat downward face on the plate is plate contact, not an overhang. A negative-volume body is a **cavity shell** (keep its winding) when its bounds lie inside a positive body's, else an inside-out mesh (flip) — flipping a cavity makes its walls read as multi-millimetre. Rays are cast against ALL bodies (a cavity wall faces the outer shell). Bundled `process-limits/starter-limits.json` rows must carry a `source`; caller numbers win.
- **Sampled, not certified:** deviation/tessellation-error numbers are sampled estimates and are labelled so; the deviation map under-reports a worst point that sits at a vertex of a small feature (measured 3.4 % low vs meshio++ `hausdorffDistance`, which is used only as a test-time oracle).

## Webview / UI conventions

- **`[hidden]` hazard (hit 8+ times):** an author `display:` rule beats the UA `[hidden]{display:none}`. Every element that is toggled with `hidden` and has an author `display` needs an explicit `#id[hidden]{display:none}` override. Tests must assert **rendered** visibility (`offsetParent !== null`), not the class/attribute.
- **Specificity traps:** `#toolbar button` paints solid blue — menu items are styled `#toolbar .tb-dropdown button, #file-dropdown button`, segments `#toolbar .tb-dropdown .sel-mode`; their box sizes feed fixed screenshot clips. Collapse CSS is `#side .side-section.collapsed` (the `#side` prefix is load-bearing against `#parts-panel{flex:1}`); the toolbar sizing rules are scoped `#toolbar > button`. Never put `display` in `#view-controls .tb-dropdown`.
- **Theme:** scene colours come from `--cad-*` custom properties via `palette.ts` (`:root` values must equal `PALETTE_FALLBACKS`; HC-light block after HC); `--ui-*` is metrics only. Chrome colours use `var(--vscode-*)`, never hardcoded hexes. `Viewer.applyTheme()` then `refreshColors()` on theme change. Part colours are immune by construction — never re-theme by writing `mat.color` across a traversal. No magenta/violet accents in chrome. No web font (CSP).
- **Part density:** `Part.density` (g/cm³) is validated by `materialDensity.ts`'s `validateDensity` at every entry (sidecar parse, `set_part`) and must be copied in `PartsModel`'s `clone()`. Mass is `volume mm³ / 1000 × density`, computed only for solids a Part lists (BOM rows, `get_mass_properties` on `solid-N`); a Part with no density or no resolved solid has `mass: null`, and any `null` row makes `totalMassGrams` `null` (never counted as zero). `set_part`'s `material` name stores the resolved number, never the name.
- **Geometry display mode** (`geometryStyle.ts`): the structure overlay (`geometryOverlay`: edge copies + one `Box3Helper` per solid) is a scene sibling of `model` like the hidden-line ghosts, so it is never picked, and it copies `model`'s position/rotation/scale (up-axis). Face fill goes through `displayOpacityFactor()` (the single opacity writer); point sprites are scaled/depth-tested in `applyGeometryPoints()` and `frame()` must apply the same factor. It is deliberately absent from the `render_snapshot`/`screenshot_shape` zod enum (webview-only) though `isDisplayMode` accepts it.
- **Materials:** built once, only mutated; Flat mode swaps to a cached `MeshBasicMaterial`, so callers of `setDisplayMode()` must re-run `refreshColors()`. Opacity composes multiplicatively against `userData.baseOpacity` (`highlightGroup()` is the only writer of `material.opacity`). Selection uses a subtle emissive (`SELECTION_EMISSIVE`), not a full accent swap, for faces.
- **Picking:** `collectTargets`/`collectSnapPoints` use `traverseVisible` (Raycaster ignores `.visible`). Measurement is a parallel pick path independent of `SelectionSet`. Selection happens on click (≤4 px drag).
- **Dropdowns** (`dropdownMenu.ts`): containment test is `trigger.contains(t) || panel.contains(t)` (icon `<svg>` clicks); dismissing `pointerdown` is capture-phase + `preventDefault`/`stopPropagation`; Escape returns focus to the trigger. Collapsible sections persist via `ViewState.collapsedPanels`; the arrival order of `geometry` / `viewState` / `parts` / `viewerDefaults` messages is non-deterministic — handlers must tolerate any order (`applyInitialViewIfNeeded`, `syncMeshSizeSeed`).
- **View state:** `Viewer.setModel()` does *not* auto-reset on first load (caller frames via `applyInitialViewIfNeeded`); edit rebuilds keep the camera direction and skip auto-reframe when the new bounds fit the last padded sphere. Opening must never write a sidecar — use silent `load()`, not `update()`. Restore handles are the same functions the toolbar calls. Loop suppression flags (`applyingLinkedCamera`, `applyingBookmark`, `hasAppliedInitialView`) are load-bearing. Explode preview and op preview are session-only.
- **Clip caps** are stencil-buffer (renderer needs `{stencil:true}`; per-source-mesh marking; structural rebuild vs cheap plane move; rebuild requests coalesced). `orientTowardBulk` keeps the surviving half non-empty — without it a face clip makes the model vanish. View the cut from the clipped-away side.
- **Icons:** `src/toolbarIcons.ts` and `src/webview/opIcons.ts` are **generated** (TikZ → `pdftocairo -svg` → `icons/build-*.mjs`; `currentColor` only, fills may map gray→opacity but strokes don't). Never hand-edit; rebuild only changed ids (`make svg-ui/<id>.svg` / `svg-ops/<id>.svg` then the build script) — a bare `make ts` churns every file. `src/uiGlyphs.ts` is the separate hand-authored line-glyph set. `pdftocairo` has no safe substitute. Design icons for 1em.
- **`viewerDom.ts` is one template literal** — a stray backtick (even in an HTML comment) ends it and surfaces as a bogus TS error elsewhere.
- **Panels are DOM-only classes with no unit test** (`partsPanel.ts`, `meshingPanel.ts`, …); logic worth testing lives in pure sibling modules. Webview-side modules the host also value-imports must stay free of `three` and DOM at module scope (`import type` for `clipping.ts` etc.). Tree group rows expand to descendant leaves (`treeGroups.ts`).
- **Other conventions worth keeping:** sidebar width is one `--side-width` custom property (resizer is the only writer; `notifyResize()` after a drag); inline renames commit on Enter/blur and **Escape restores before blurring**; icon-only controls get `aria-label` mirrored from `title` by a MutationObserver; Advanced group holds read-only/library panels (badge counts eligible children).

## MCP server (`src/mcpServer.ts` → `mcpTools.ts` → `mcpSidecars.ts`)

- **Module split:** `mcpServer.ts` = SDK wiring + zod; `mcpTools.ts` = handlers over an injected `Pipeline`, importing only `import type` from WASM-touching modules; `mcpSidecars.ts` = node-fs sidecars. `extensionPath` = bundle dir's parent (or `CAD_PREVIEW_ROOT`).
- **Stateless per call; sidecars are the state.** Ops are raw JSON through `validateEditOp`. The CAD source is only ever written by `save_model`; every other output path goes through `assertNotSourcePath`.
- **Central `registerTool` decorator** adds: unknown-parameter warnings (schemas re-registered as `z.looseObject`; declared keys passed through unchanged), the `expectedRevision` guard, and per-request job scoping (`jobScope` AsyncLocalStorage → kernel `JobOptions` so `notifications/cancelled` cancels exactly that request). `wrap()` supplies progress callbacks (start/done only — Gmsh has no progress hook) and turns `images[]` into image content blocks; thrown errors become coded `structuredContent` (`mcpErrors.ts`: `kernel-timeout`, `job-cancelled`, `kernel-reset`, `kernel-crashed`, `unsupported-source`, `source-timeout`, `source-conversion-failed`, `dirty-buffer`, `stale-revision`, `tool-error`; the text block still leads with the message). `describe_capabilities` is the one tool outside `wrap()`.
- **Conventions:** tools report **facts**; the agent renders pass/fail/need-more-info (`verdictConventions`); a missing capability (no Playwright, no openscad, mesh source for a B-rep-only tool) returns `supported:false` + reason rather than throwing (tools with no such shape throw a clear error). Every caller-supplied cap is reported (`truncated`/`warnings`), never silent. Caller-input shape errors fail fast; unresolvable ids degrade to warnings. Mesh-source inspection is raw-file (edits are *not* baked for `inspect`/`get_mass_properties`/`measure`/`promote_mesh_to_brep`/`repair_mesh`; they *are* baked for meshing, export, `compare_models`, drawings and `save_model`). A meshio-only source has no directly exposed triangle array, but `get_mass_properties`, `measure` and `compare_models` read the welded boundary surface `meshioBoundarySide.ts` derives from meshio++'s extraction and mark it `surfaceDerived`; `inspect` and the mesh-healing tools still refuse it. `measure` uses bbox centre (not centre of mass); `measure_exact` is B-rep only. Queue-managed `export_mesh` writes an atomic job receipt first; `job_status`/`job_cancel` are owner-checked; a receipt with no live kernel record after restart is `uncertain`, never replayed. Remesh outputs are created exclusively; a MED/Parts-sidecar pair is not a transaction.
- **Smoke harness traps:** accumulated WASM heap pressure over the very long run causes reproducible `memory access out of bounds` aborts at arbitrary calls — wrap such a call in `callWithCleanRetry(name, args, resetState)` whose `resetState` restores every file it touches (a blind retry double-appends sidecar ops). `callTolerant` assertions pin *known upstream failures* so a fix flips them. Regexes over MDPA `SubModelPart` blocks must anchor on line ends (`End SubModelPartNodes` precedes `End SubModelPart`).
- **VS Code registration** (`mcpRegistration.ts`, pure snippets in `mcpClientSnippets.ts`): the provider id `cad-preview.mcp` must equal `contributes.mcpServerDefinitionProviders[].id`. The server is launched with `process.execPath` + `ELECTRON_RUN_AS_NODE=1` (the kernel-worker `fork` inherits it, so keep `fork` env-inheriting). VS Code's `.vscode/mcp.json` uses a `servers` key; every other JSON client uses `mcpServers`.
- **Roadmap-linked data:** starter macros (`macros/starter-library.json`), mesh presets (`mesh-presets/`), sheet templates (`sheet-templates/`) are copied to `dist/` by `esbuild.mjs` and merged under a caller library (caller wins, collisions reported); they're read-only in the panel. `tools/list` count is asserted in `mcp:smoke` — bump it when adding a tool.
